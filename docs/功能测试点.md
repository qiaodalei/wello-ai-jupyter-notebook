# Wello AI Jupyter 功能测试点

对照需求说明 MVP，下面是应覆盖的手工 Jupyter、内核、文件、Agent 闭环和产品约定。脚本 `scripts/run_tests.py` 对可自动项逐项打分。

## A. 产品与页面

| ID | 测试点 | 期望 |
|---|---|---|
| A1 | 页面标题与品牌名 | 浏览器标题和顶栏为 **Wello AI Jupyter** |
| A2 | Notebook 主界面不出现 API Key / 模型输入 | 主页面无密钥表单 |
| A3 | 模型配置独立页面 | `#config` 可打开配置页，含 Base URL / Key / 模型 |
| A4 | 前端可访问 | `http://127.0.0.1:5173` 返回 200 |
| A5 | 后端健康检查 | `/api/health` 内核存活且 idle/busy |

## B. 单元格基础

| ID | 测试点 | 期望 |
|---|---|---|
| B1 | 插入 Code 单元格 | 新增 `cell_type=code` |
| B2 | 插入 Markdown 单元格 | 新增 `cell_type=markdown`，源码可保存标题 |
| B3 | 编辑代码源码 | PATCH 后 GET 能读到新 source |
| B4 | 删除单元格 | 删除后数量减少；删光会留下一个空格 |
| B5 | 上移 / 下移 | 单元格顺序改变 |
| B6 | Code ↔ Markdown 切换 | 类型切换成功，Markdown 无 outputs |
| B7 | 复制语义（插入相同源码） | 新格 source 与原格一致 |

## C. 执行与输出

| ID | 测试点 | 期望 |
|---|---|---|
| C1 | `print(1+1)` | stdout 为 `2`，status=ok，有 execution_count |
| C2 | 语法 / 运行错误 | `1/0` 得到 `ZeroDivisionError`，traceback 含 ANSI 或错误名 |
| C3 | 内核仍可用 | 报错后下一格 `print("ok")` 仍成功 |
| C4 | 流式 stdout | 多行 print 全部出现在 outputs |
| C5 | 清空单个输出 | clear 后 outputs 为空 |
| C6 | 清空全部输出 | clear-outputs 后所有 code 格无输出 |
| C7 | Run All | 多个 code 格按序执行，后格能用前格变量 |

## D. 内核控制

| ID | 测试点 | 期望 |
|---|---|---|
| D1 | 中断执行 | `time.sleep(30)` 在数秒内被 interrupt，不以正常 ok 结束 |
| D2 | 重启内核 | 重启前赋值的变量，重启后读取应报 `NameError` |
| D3 | 重启后源码仍在 | 单元格 source 不被清空 |

## E. 文件与格式

| ID | 测试点 | 期望 |
|---|---|---|
| E1 | 保存 `.ipynb` | dirty=false，磁盘文件存在 |
| E2 | 打开 `.ipynb` | 打开后单元格源码与保存时一致 |
| E3 | 导出可被 nbformat 读取 | nbformat v4，含 kernelspec |
| E4 | 官方 Jupyter 兼容字段 | code 格含 source / outputs / execution_count |

## F. Agent 闭环

| ID | 测试点 | 期望 |
|---|---|---|
| F1 | 未配置模型时有明确提示 | 不假装已经跑完实验 |
| F2 | 配置页与 `.env` 是唯一入口 | 主界面源码无 API Key 输入框 |
| F3 | 写入必须落在单元格 | Agent 工具含 insert/replace/run_cell |
| F4 | 自动执行开关存在 | settings.auto_execute 可读写 |
| F5 | 有限修复轮数 | settings.max_repair_rounds 默认 5，可更新 |
